External mutation: none

## 1. Purpose

`TRIGGER-DEF-001` defines the public-facing rule language for TerraNova trigger
work. It exists to prevent three failure modes:

1. Reducing a trigger to a flat number.
2. Publishing protected or private material as if it were public canon.
3. Promoting source-backed references into executable or canonical modules too early.

This draft is public-capable in structure, but it is not a publication release.
It still requires human review before public use.

## 2. Non-Goals

- This draft is not final public canon.
- This draft does not assign canonical TRG identifiers.
- This draft does not publish raw ChatGPT exports, raw excerpts, page titles, local paths, conversation IDs or account data.
- This draft does not make medical, financial, legal, patent, tokenomics or contract claims.
- This draft does not expand Metarotik beyond a deferred relation marker.
- This draft does not authorize Notion writes, GitHub pushes, PRs, token actions or publication.

## 3. Core Rule

`Trigger-ID` is not the unique trigger entry key.

The unique trigger entry key is:

```text
Trigger-ID + Layer/Instanz + Modus/Promille + Kontext
```

This means a single visible ID can have more than one legitimate entry if the
layer, instance, mode, promille or context differs. Public documentation must
not collapse those entries into one flat number row.

## 4. Definitions

| Term | Draft Definition | Public Boundary |
| --- | --- | --- |
| Trigger | A named cognitive, operational or system steering unit that can be referenced, reviewed and governed. | A Trigger is not automatically an executable command, medical claim or public canon object. |
| Trigger-ID | The visible numeric or symbolic identifier used to address a trigger family or slot. | Trigger-ID alone is not a unique trigger entry. |
| Unique Trigger Entry Key | Trigger-ID plus layer/instance plus mode/promille plus context. | Do not collapse multiple instances into one flat number row. |
| Trigger Instance | A concrete occurrence of a trigger within a layer, mode, person, context or implementation surface. | Instance detail can be protected if it reveals private identity, account or security context. |
| Trigger Cluster | A semantic grouping of triggers sharing a functional, thematic or control purpose. | Cluster membership is routing evidence, not proof of L3/L4 canon. |
| Trigger Band | A numeric or symbolic range used to group source-review and publication work. | Band-level rules must not invent per-trigger semantics. |
| Trigger Layer | The source, control, execution or publication layer where a trigger is observed or used. | Layer movement requires gates; L2 reference does not imply L3 execution. |
| Experienced | A trigger was observed in lived, operational or session context but is not necessarily defined. | Experience-derived material may be public after professional framing; third-party/private specifics remain protected. |
| Defined | A trigger has a source-backed name and definition candidate. | Defined does not equal stable public canon. |
| Emergent | A trigger pattern exists as correlation or candidate relation but lacks enough source-review depth. | Emergent rows stay out of public canon. |
| Active | A trigger is used in bounded command or routing practice. | Active command surfaces need mutation and incident gates. |
| Stable | A trigger has enough source, gate and publication review to be treated as durable within its level. | Stable level must be named: L1, L2, L3 or L4. |
| Public | Material that may be published after source, framing and redaction gates pass. | Public must preserve correlation without exposing third parties, accounts, raw identities, security or protected IP. |
| Internal | Material usable inside the workspace or repo trace but not released as public canon. | Internal can be summarized by handle but not fully exported by default. |
| Metarotik | A recognized later trigger/phenomenology cluster that must be preserved as relation but not expanded in this scaffold. | Deferred until after trigger/tokenomics basis is stable. |
| Protected | Material whose relation can be preserved but whose detail is blocked by IP, legal, business, security, account, third-party or sensitivity gates. | Protected means handle-level relation only unless explicit review and Silvan publication GO clears more. |
| Silvan-Specific Material | Source material anchored in Silvan's authorship, lived system work or workspace history. | Not private by default; public after professional framing, with third-party/account/raw-identity/security/IP exceptions. |

## 7. Silvan Framing Rule

Silvan-specific material is not private by default.

If the material is authored by Silvan, grounded in Silvan's system work, or
necessary to understand TerraNova/FerrAI structure, the default action is to
frame it professionally and preserve its correlation. The goal is not to hide
the author, erase lived development history or destroy the relation graph.

Public handling changes only where a protected category applies.

## 8. Protected Exceptions

- Third-party identities and raw third-party context.
- Accounts, addresses, credentials, credential material, security details and operational secrets.
- Raw identities, intimate real names and unreviewed private biographical details.
- Patent claims, filing strategy, protected technical detail and unreviewed IP specifics.
- Tokenomics promises, financial wording, sales wording and contract mechanics.
- Raw transcripts, raw excerpts, local file paths, page URLs and conversation identifiers.

Protected does not mean deleted. Protected means the relation may be preserved
at handle level while protected details stay blocked until explicit review and
Silvan publication approval.
