# TOC Review Checkpoint (2026-05-01)

## Ziel

Schneller Struktur-Check für Inhaltsverzeichnis, Abstract und frühe Kapitel,
bevor die nächsten großen Batches einsortiert werden.

## Prüffokus

1. Kapitelreihenfolge konsistent?
2. Kapitelbezeichnungen stabil (keine Doppelbenennung)?
3. Abstract deckt den realen Werkstand (500er-Ziel) ab?
4. Anhangstrennung klar (Kern vs. Companion vs. Evidenz)?
5. Track-Hinweise (A/B/C) indirekt in der Kapitelarchitektur nachvollziehbar?

## Checkliste

| Prüffeld | Status | Notiz |
|---|---|---|
| TOC vollständig | ⬜ | |
| TOC-Nummerierung konsistent | ⬜ | |
| Abstract aktuell | ⬜ | |
| Kapitel 1 Scope klar | ⬜ | |
| Appendix-Abgrenzung klar | ⬜ | |
| Verweise auf Intake/Runbook vorhanden | ⬜ | |

## Übergabepaket für den Review

- Inhaltsverzeichnis (aktuelle Fassung)
- Abstract (aktuelle Fassung)
- Kapitel 1 (mindestens)
- optional: Kapitel 2, wenn bereits stabil

## Output nach Review

1. Kurzprotokoll „TOC ok / needs fix“
2. Liste mit maximal 10 Strukturkorrekturen
3. Entscheidung: sofort weiter mit Batch-Ingestion oder erst TOC-Fix
